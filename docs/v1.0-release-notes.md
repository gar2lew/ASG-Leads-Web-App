# v1.0 Release Notes

Release: v1.0 Internal Production Release Candidate
Date prepared: 2026-07-06
Branch: `goal/v1-release-candidate`
Savepoint: `savepoint-before-v1-release-candidate`

## Release Status

This is a release candidate package for human review.

It is not a production deployment approval. Firebase deploys, live Salestrail sync, phone backfill writes, migration scripts, and production data writes remain blocked until separately approved.

## Audience

- Reps
- Managers
- Admins
- Directors
- Release manager

## Summary

v1.0 prepares ASG CRM for controlled internal production readiness review. The candidate brings together the stabilisation, workflow, validation, emulator, production-readiness, AI foundation, and staff UAT documentation completed across the recent goal chain.

The release candidate is locally validated and ready for human review. It is not ready for unrestricted production deployment until staff UAT, backup and recovery rehearsal, explicit Firebase approval, and final go/no-go sign-off are complete.

## What Is Included

### Engineering foundation

- Codex operating contract, handbook, playbook, roadmap, goals, standards, git strategy, testing standard, release process, and security guidelines.
- Goal branch and savepoint workflow.
- Risk register, decision log, internal changelog, known issues, pending decisions, feature backlog, product release tracking, and project state documents.
- Repository intelligence documents for health, ownership, dependency map, and technical debt.

### Validation foundation

- Root validation scripts for typecheck, lint, test, build, and emulator checks.
- Firebase emulator preflight, Firestore rules harness, Firestore smoke test, and callable dry-run harness.
- Functions build and settings/admin callable test coverage.
- Documented Java and emulator setup.
- Documented callable emulator coverage for PIN, settings/admin, phone normalisation dry-run, and Salestrail source-contract checks.

### Staff workflow and UI foundation

- Design system documentation.
- Component audit and refactor plan.
- Shared UI primitives for buttons, cards, dialogs, form fields, badges, loading states, and tables.
- Staff workflow improvements across navigation, Dashboard, Leads, Lead Details, Admin, My Settings, Reports, and System Controls.
- Production-sensitive controls made clearer in the UI and release docs.

### Firebase and release safety

- Firebase release plan.
- Emulator validation checklists and run plans.
- Firestore architecture review and optimisation plan.
- Internal production readiness Go/No-Go report.
- Staff UAT plan.
- Approval gates for hosting, Functions, Firestore rules, Firestore indexes, migrations, phone normalisation, and Salestrail.

### AI and data foundation

- AI Foundation audit for lead timeline, history, notes, calls, appointments, status history, documents, tasks, and recommendations.
- Documented gap that AI should remain read-only and advisory until a permission-aware context model and approval gates exist.

2. Backup and recovery runbook approved.
3. Rollback owner assigned.
4. Release tag and merge state verified.
5. Known issues reviewed and accepted or closed.
6. Critical Firebase, callable auth, and permission risks remediated or formally risk-accepted.
7. Exact Firebase deploy surfaces approved one by one.
