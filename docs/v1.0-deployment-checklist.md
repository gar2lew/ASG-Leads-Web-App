# v1.0 Deployment Checklist

Release: v1.0 Internal Production Release Candidate
Date prepared: 2026-07-06
Branch: `goal/v1-release-candidate`

## Deployment Position

This checklist is for human release planning only. It does not approve a deployment.

No Firebase deploy command should run until the release owner gives explicit approval for the exact surface being deployed.

## Absolute Stop Conditions

Stop immediately if any item is true:

- Working tree is dirty before deployment.
- Branch or commit is not the approved release candidate.
- Firebase project target is unclear.
- Required validation has not passed on the final candidate.
- Staff UAT is incomplete or failed.
- Backup or rollback owner is missing.
- Production Firebase approval is missing.
- A migration, live Salestrail sync, or phone backfill write is included without explicit approval.
- Any secret would be printed, exposed, or committed.

## Required Validation

Run on the exact candidate before any deploy approval:

```powershell
npm run typecheck
npm run lint
npm test
npm run test:emulator:preflight
npm run test:emulator:rules
npm run test:emulator:firestore-smoke
npm run test:emulator:callables-dry-run
npm run build
cd functions
npm run build
npm run test:settings-admin
cd ..
git diff --check
```

Expected known warnings:

- Vite large chunk warning for Firebase and PDF vendor chunks.
- `firebase-functions` outdated SDK advisory during callable emulator startup.
- Permission-denied logs during negative Firestore rules checks.

These warnings do not block review by themselves, but they must remain documented.

## Firebase Surface Checklist

### Hosting

Allowed only after approval.

Before hosting deploy:

- Client typecheck passed.
- Production build passed.
- Staff UAT passed for login, dashboard, leads, reports, admin settings, and mobile lead workflow.
- Release metadata is intentional.
- Rollback target is known.

Approval status: Pending

### Functions

Allowed only after explicit approval.

Before Functions deploy:

- Functions build passed.
- Callable dry-run emulator tests passed.
- Exported functions reviewed against expected surface.
- Callable auth gaps remediated or formally risk-accepted.
- Secrets are referenced by name only.
- Migration, phone backfill, and Salestrail live sync callables are not invoked.

Approval status: Pending

### Firestore Rules

Allowed only after explicit approval.

Before rules deploy:

- Emulator rules tests passed.
- `salestrailCalls` direct reads and writes remain denied.
- App settings and audit write paths remain callable-authoritative.
- Broad operational access risk is accepted or remediated.
- Current app compatibility paths still work.

Approval status: Pending

### Firestore Indexes

Allowed only after explicit approval.

Before indexes deploy:

- Query and index mapping reviewed.
- Any index build delay is acceptable.
- Rollback limitations understood.

Approval status: Pending

### Migration Scripts

Not approved for v1.0 release deployment.

Required before any future migration:

- Full runbook.
- Backup/export.
- Dry-run validation.
- Duplicate handling.
- Rollback plan.
- Explicit full-run approval.

Approval status: Blocked

### Phone Normalisation Backfill

Write mode is not approved for v1.0 release deployment.

Required before `dryRun:false`:

- Dry-run first.
- Count of affected leads.
- Sample before and after review.
- Backup/export.
- Explicit approval.
- Post-run reconciliation.

Approval status: Blocked

### Salestrail Sync

Live sync is not approved for v1.0 release deployment.

Required before future live sync:

- Secret names present by name only.
- No-network mock seam or equivalent safe coverage.
- Dry-run without writes.
- Controlled live test approval.
- Imported count reconciled to `salestrailCalls` document count.
- Direct client reads remain denied.

Approval status: Blocked

## Deployment Command Plan

No command below should run without explicit approval.

Preferred staged approach:

1. Hosting only, if approved:

```powershell
firebase deploy --only hosting
```

2. Functions only, if approved:

```powershell
firebase deploy --only functions
```

3. Firestore rules only, if approved:

```powershell
firebase deploy --only firestore:rules
```

4. Firestore indexes only, if approved:

```powershell
firebase deploy --only firestore:indexes
```

Do not run unscoped `firebase deploy` unless every surface has explicit approval.

## Post-Deployment Checks

After an approved deployment:

- Confirm release metadata in Admin settings.
- Smoke test login.
- Smoke test dashboard.
- Smoke test lead list and lead detail.
- Smoke test call logging using approved test data only.
- Smoke test reports.
- Smoke test Admin system health.
- Check Firebase console for Functions errors if Functions were deployed.
- Monitor Firestore permission errors.
- Record deployment result and rollback tag.
